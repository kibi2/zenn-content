以前、「tirenvi」を作ったお話をしました。

https://zenn.dev/ogwk/articles/d5780b268e97b3

ただし最初から考えていたのは、単なるCSV/TSVエディタではなく、

> テキストの中に表が埋め込まれている状態を自然に扱うこと

でした。

つまり、Markdown（GFM）のように

* テキストの途中に表がある
* 表は構造を持っている
* それでも最終的にはテキストとして壊れてはいけない

という状態を前提に設計しています。

## v0.1.0と今回の違い

v0.1.0では、

* 表単体のケース

にフォーカスして、安定して編集できる状態を作りました。

そして今回のv0.3.0では、

* テキストと表が混在した状態

でも問題なく扱えるようになりました。

設計自体は最初から想定していましたが、
それがようやく実用的な形になった、という位置づけです。

## デモ

![](https://static.zenn.studio/user-upload/1acba38a07b6-20260421.gif)

Raw Markdown → structured table view → adjust column widths → edit cells → back to raw Markdown

往復してもフォーマットは壊れません（lossless round-trip）。
テキストと表が混在したまま編集できます。

## できるようになったこと

* テキストと表が混在したMarkdownをそのまま編集できる
* セル内改行を維持したまま編集できる
* 列幅を調整できる（数値指定・増減、自動調整、繰り返し可能）
* Vimの操作でそのまま扱える

## GFMだけではない

**Pukiwiki形式**もサポートしています。

GFMに比べるとかなりマイナーですが、
tirenviとしてはどちらも同じTIR（構造化された表）として扱っています。

特定のフォーマットに依存するのではなく、

> 「テキストの中に埋め込まれた表を扱う」

という視点で設計しています。

## tirenviはGFMエディタではない

ここは少し重要なポイントです。

tirenviは **GFMエディタではありません**。
あくまで「TIR（構造化された表）を編集するためのエディタ」です。

Markdown（GFM）は、その応用先のひとつに過ぎません。

Markdownを編集しているというより、

> 構造化された表を、安全に往復可能な形で編集している

という感覚に近いです。

## 今後について

次に考えているのは：

* **tirenvi for VSCode**

今回、Neovim上でTIRエディタとしての基盤ができたので、
同じコンセプトをVSCodeでも実現できるかを検討しています。

まだ計画段階ですが、

* Vimに依存しない形でのTIR編集
* より広いユーザーへの展開

といった可能性があります。

## まとめ

今回のv0.3.0で、

「表を編集するツール」から
「テキストと表が混在するドキュメントを扱えるツール」

に一歩進んだと感じています。

設計としては最初から目指していた形に、ようやく到達しつつあります。
