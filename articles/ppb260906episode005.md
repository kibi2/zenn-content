## okozeとcanvasの分離 

前回はindex.html、style.css、main.jsの三つのファイルを作りました。

このうちmain.jsがokoze本体です。index.htmlとstyle.cssは、okozeをWebページに貼り付けて使うためのサンプルです。

okozeは特定のHTMLページに依存するものではなく、Canvasを使って動くものにしたいと思っています。

HTMLには複数のCanvasがあるかもしれません。そこで、Canvasとokozeを結びつけるため、Canvasにid="okoze"を付けることにします。

```html
<canvas id="okoze" width="400" height="300"></canvas>
```

```javascript
const canvas = document.getElementById("okoze");
```

これで、HTML側のCanvasとokoze本体を分離できます。

## &#128308;イメージの上に矩形(正方形)を描く(一辺の長さは画像の短辺の8割、センタリング) 

これが最初にクリアすべきテスト項目です。
9x9のグリッドの前に外枠の矩形だけ描くことにします。

:::message
図形処理の世界では長方形と呼ばずに矩形と呼びます。なぜでしょう？AIに聞いてみました。

**A. 矩形は正方形も含むが、長方形は正方形を含まないから**

だそうです。なるほどね。台形とかも四角だから四角も使えないしね。すごく要約しているので正確にはAIに聞いてみてください。
:::

実装する前に座標系を決める必要があります。この手のパズルは左上が原点で、X軸は右方向、Y軸は下方向です。
スプレッドシートの座標系と同じです。Canvasの座標系も同じなので、そのまま使います。

そして次に矩形をどう表現するか決めないといけません。

:::message
普通は左下角の座標と右上隅の座標です。ですが図形処理では左下角の座標と対角線のベクトルを持つとメリットがあります。なぜだと思いますか？これもAIに聞いてみましょう。

**A. 座標変換で有利だから**

ちょっと期待した答えと違いました。私が用意した答えはこちらです。

**A. 両隅の座標を持つと平行移動で面積が変わるから**

面積=幅*高さ、です。両角の座標を持つ方式だと幅を求めるため差を計算しないといけません。ここで桁落ちが発生してしまいます。 つまり平行平行移動すると幅と高さが変わるのです。対角ベクトルは幅と高さを持つので面積は変わりません。 まあ実際これが問題になることは滅多にないでしょうが、心配性の図形処理屋は頭を悩ませます。

といってもこの方式にはデメリットもあります。右上角に点があった場合、平行移動すると右上角と点の座標が一致しません。同じ点かどうかは精度を考慮して判断しないといけません。なのでお手軽な方式は両角の座標を持つことです。

そこで折衷案が出てきます。矩形は両角の座標を持ち原点付近で定義する。平行移動は別に別(行列)で定義する。平行移動しても矩形のデータを書き換えない様にするのです。どちらにしろ複雑になります。
:::

矩形クラスを作りましょう。名前はRectです。左下角の座標と右上角の座標を持ちます。
座標のクラスも作りましょう。名前はVec2dです。X座標とY座標を持ちます。
座標なのでCoord2d, Point2d などが良いかもしれませんがベクトルも座標も同じ様にXY座標を持つだけですから同じクラスを使いましょう。

## 描画クラスを作る

canvasに描画しますが、ここは一つ間に描画クラスgraph2dを挟むことにします。
こうしておけばズーム、パンとか言ったカメラ操作もここで全部吸収できるので便利です。
将来Canvas以外に描くことになっても安心です。

```js
class Graph2d {
  constructor(ctx) {
    this.ctx = ctx
  }
  drawrect(rect) {
    ctx.strokerect(
    rect.p0.x,
    rect.p0.y,
    rect.getwidth(),
    rect.getheight(),
  )
}
```

```js
class Rect {
  draw(graph) {
    graph.drawRect(this)
  )
  getWidth
  getHeight
}
```
